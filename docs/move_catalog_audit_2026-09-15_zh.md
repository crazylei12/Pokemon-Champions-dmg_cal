# 标准版招式缺项彻查与修复

## 范围与来源

仅修改 Android 标准版 `main`。核对游戏 1.2.0、Master Data v18 的已有客户端导出，重新计算 `waza.json`、`waza_learn.json`、`personal.json` 的 SHA-256，与已提交的来源记录一致。原始文件仍保留在仓库外，提交内容只包含所需的编号、名称、形态与学习关系。

客户端共有 920 条招式记录，其中 `available=1` 为 512 个；完整学习表覆盖 396 个客户端形态。原始学习表也包含未开放招式，必须先按 `available` 过滤，不能直接把所有历史招式都放进选择列表。

## 为什么之前修过还会缺

此前修复了已确认我方招式被静态池裁剪，以及 Champions 形态学习来源回退错误。这两项保护仍保留。

本次是另外三个缺口：

1. 新开放的招式在旧 Showdown 基线仍标为 `Past` / `Custom`，计算库准备脚本将它们过滤。
2. 学习表导出遇到计算库缺项直接返回 `null`，中文名称和队伍码映射又依赖不完整目录，形成连锁遗漏。
3. 原回归仅验证导出后仍存在的条目，不能发现已被过滤掉的招式；形态家族回退也会掩盖精确形态的差异。

精确核对 396 个客户端形态，修正 **超级雌性超能妙喵（Meowstic-F-Mega）** 和莫鲁贝可空腹花纹（Morpeko-Hangry）的错误学习关系：前者补入预知未来、神通力并移除错用雄性来源的五招；后者移除客户端空腹形态未列出的五招。超级戟脊龙和低调颤弦蝾螈等形态也获得此前被全局过滤的专属招式。导出直接使用精确客户端形态表，不再依赖家族回退猜测。

计算联动验证还发现并修复：

- 庞克摇滚对声音招式的攻击加成及防御减伤，包含破格和化学变化气体条件。
- 化学变化气体压制默认特性后，Smogon 克隆对象重新带回默认特性的漏洞。只清除本次请求对象的默认回退，保留全局物种数据和用户配置。

电光双击进入直接伤害计算。复生祈祷、换档、换场作为变化招式保留并显示无直接伤害；本次没有新增回合模拟、自动复活或自动改变队伍状态。

## 防止再次漏项

- `sync-champions-moves.mjs` 从经过哈希验证的完整客户端表生成 `champions-moves.v18.json`，同时维护数字映射。未知编号、重复映射、缺形态或来源哈希不符立即失败。
- 导出缺计算器招式或中文名称时抛出错误，不再静默丢弃。
- `android:assets` 和资源更新流程运行 `validate-champions-moves.mjs`，从全部 512 个客户端可用招式及 396 个形态反向验证计算库、中文词库、数字映射、界面参数及完整学习集合。
- 普通构建使用已提交中文资产；发现缺项即失败。中文生成仍由资源更新步骤显式执行，普通构建不额外依赖远程翻译快照下载。
- 负向回归主动移除电光双击、复生祈祷名称和编号，并向巴布土拨学习表注入错误招式，确保这些故障确实能被检查发现。
- 保留已确认我方招式优先、对手未知招式受合法池约束，以及未知队伍码编号拒绝保存的保护。

重新导入同一份 v18 客户端数据：

```powershell
node tools/team-code-resolver/sync-champions-moves.mjs <仓库外的已解密主数据目录>
node tools/android/prepare-champions-calc.mjs
node tools/localization/sync-zh-hans.mjs
npm.cmd test
```

新版本客户端不能直接绕过哈希锁，需先更新来源版本与哈希、完整形态映射，再重建上述清单并运行全量检查。
