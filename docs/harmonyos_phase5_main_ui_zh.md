# HarmonyOS 阶段 5：主应用界面与非截图业务流程验收记录

日期：2026-08-01

状态：**已完成（模拟器与非截图范围）**

## 1. 阶段边界

本阶段将 Android 现有首页、自由伤害计算、对局助手和设置界面移植为正式 ArkUI 主体，并接入阶段 3 的本地伤害引擎与阶段 4 的持久化仓库。本阶段不读取屏幕、不请求截图或悬浮窗授权，不把后续识别流程伪装成已完成功能。

页面保持 Android 1.1.4 的中文信息层级和已有产品术语；没有增加调试入口、测试图片选择、ROI、Top-3 或内部文件名称等开发概念。

## 2. 已实现内容

### 2.1 正式主框架

- 底部四个主入口：首页、计算、对局、设置；
- 首页显示本地引擎状态、已保存队伍和用户宝可梦配置；
- 标准版与录屏功能版共用 bundle 和数据，但首页标识、应用标签和更新下载默认选项由产品配置分开；
- 长内容统一使用可滚动容器，主操作使用全宽或弹性布局，底部导航独立于页面滚动区。

### 2.2 队伍与用户配置

- 已保存队伍可预览、带入计算、重命名、删除和逐只手动调整；
- 队伍只有在六只宝可梦、实际能力值、特性和至少一个招式完整时才标记为可用于计算；
- 用户对手配置可新建、搜索、修改、删除和用于自由计算；
- 搜索同时匹配本地化中文名、英文/Showdown ID、别名和用户配置名；
- 实体选择页根据当前宝可梦限定合法招式，不用通用 Gen 9 招式池替代 Champions 规则。

### 2.3 自由伤害计算

自由计算可设置攻守方向、宝可梦、等级、特性、道具、招式、实际能力值、能力加点、单打/双打、天气、场地、双方墙、会心和范围招式。请求使用完整精确配置调用同一本地 Smogon 引擎，结果显示伤害百分比、生命值区间、击倒次数、假设和警告。

模拟器实际点击验收得到：

- 攻击方：皮卡丘；
- 防守方：红莲铠骑；
- 招式：百万吨重踢；
- 结果：`18.1% – 21.9%`，`29 – 35` 点生命值，可能 5 次击倒。

这一结果由正式计算页的“计算伤害”按钮产生，不是隐藏测试页伪造。

### 2.4 更新、备份和分享

- 设置页可选稳定版/预览版频道，只在用户主动点击时访问 GitHub；
- 语义版本比较正确处理 `v` 前缀、预发布标识和稳定版优先级；
- 发布资产按标准版/录屏功能版区分，优先选择 arm64 包，然后交给系统浏览器、下载和安装确认流程；
- 在模拟器上实际执行稳定版检查，返回“当前已经是此频道的最新版本（v1.1.4）”；
- 当前公开 Release 没有 HarmonyOS 安装包，因此页面如实提示前往发布页，没有将 Android APK 误当鸿蒙包；
- 整包备份和用户配置分享使用系统文档选择器，读写后继续使用阶段 4 的完整校验、原子写入和回滚。

## 3. 自动化与模拟器验收

执行：

```powershell
npm.cmd run harmonyos:phase5:check
npm.cmd run harmonyos:phase5:emulator
```

Node 验收共 6 项，覆盖正式页面入口与产品文案、双向精确伤害请求、结果本地化、队伍编辑校验、中英文/配置搜索、语义版本与频道选择，以及权限清单。

模拟器一键流程完成：

1. 覆盖安装标准版，等待资源与伤害引擎真实就绪；
2. 验证首页、队伍和已保存配置数据可见；
3. 打开用户配置管理页，验证搜索和新建入口；
4. 打开自由计算页，滚动到提交按钮并执行一次真实计算；
5. 验证伤害百分比区间、对局助手说明页和设置页的更新/备份入口；
6. 不清数据覆盖安装录屏功能版，验证产品标识切换且共享数据仍在；
7. 重新安装标准版并回到正常首页。

可提交的 UI 层级证据位于 `harmonyos/app/evidence/pc-stage5-*.json`，其中标准版首页、配置管理、实际计算结果、对局页、设置页和录屏版首页都有独立快照。过滤日志按仓库规则仅保留在本地。

## 4. 阶段退出结论

阶段 5 的正式主体、队伍/用户配置管理、自由计算、手动更新、文档备份入口和双产品界面门已关闭，可进入阶段 6 的相册全屏取帧和我方两页 OCR。
