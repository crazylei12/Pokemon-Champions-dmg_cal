# HarmonyOS E4 双端空状态 UI 对照结论

## 结论

本轮以 Android 当前标准版与回放版为结构基线，在 HarmonyOS API 24 x86_64 模拟器上对同一版本的标准版与回放版正式产品页面进行新装后截图。首页、自由计算、对局、设置四个主页面共形成 8 组 Android/HarmonyOS 配对。人工复核未发现文本裁切、控件重叠、错误导航选中态或标准版/回放版文案串线。

本结论只关闭空状态即可完整判断的 `UI-001`、`UI-002`、`UI-006`、`UI-015`。它不替代读屏、键盘、长文本、危险操作、授权后状态、真实队伍数据、刘海/折叠屏或 ARM64 真机验收。

## 平台适配判定

- 状态栏、系统手势条、字体渲染和底部导航图标由各平台提供，允许视觉形状不同。
- HarmonyOS 纵向可用空间更大，首页内容采用垂直居中；Android 更靠上。两者没有遮挡关键信息，判定为合理响应式差异。
- HarmonyOS 卡片层级更紧凑、主按钮更宽；标题、状态、主操作、次级操作和导航顺序与 Android 一致。
- 对局页的悬浮能力由 HarmonyOS 系统确认，不复制 Android 独立“授予悬浮窗权限”按钮；此差异与平台权限模型一致。
- 计算页对手配置的空白选择器属于无意退化，已在 `eb22803` 修复，并由最终标准/回放 HAP hierarchy 与截图共同确认“无加点”可见。
